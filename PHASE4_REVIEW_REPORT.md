## Обзор реализации

## ✅ Проверенные требования

### 1. Константы валидации (строки 49-53 в session.go)
- ✅ `MaxAudioBufferSize = 1 << 20` (1MB) - корректно определена
- ✅ `MaxPacketSize = 1500` (стандартный MTU) - корректно определена
- ✅ `MaxJitterBufferSize = 1000` - корректно определена
- ✅ `MaxPtime = 100` - корректно определена

### 2. Валидация в критических функциях

#### SendAudio() и SendAudioRaw()
- ✅ Проверка размера аудио данных перед обработкой
- ✅ Возвращается `MediaError` с кодом `ErrorCodeAudioSizeInvalid`
- ✅ Сообщение содержит информацию о превышении размера

```go
if len(audioData) > MaxAudioBufferSize {
    return &MediaError{
        Code:      ErrorCodeAudioSizeInvalid,
        Message:   fmt.Sprintf("размер аудио данных превышает максимальный: %d > %d", len(audioData), MaxAudioBufferSize),
        SessionID: ms.sessionID,
    }
}
```

#### handleIncomingRTPPacketWithID()
- ✅ Проверка размера пакета перед обработкой
- ✅ Использует `handleError` с кодом `ErrorCodeAudioSizeInvalid`
- ✅ Передает `rtpSessionID` для отслеживания источника

```go
if len(packet.Payload) > MaxPacketSize {
    ms.handleError(&MediaError{
        Code:      ErrorCodeAudioSizeInvalid,
        Message:   fmt.Sprintf("размер RTP пакета превышает максимальный: %d > %d", len(packet.Payload), MaxPacketSize),
        SessionID: ms.sessionID,
    }, rtpSessionID)
    return
}
```

#### JitterBuffer.PutWithSessionID()
- ✅ Проверка количества пакетов в буфере
- ✅ Возвращает ошибку с детальной информацией
- ✅ Защищает от переполнения буфера

```go
if len(jb.packets) >= MaxJitterBufferSize {
    return fmt.Errorf("jitter buffer переполнен: количество пакетов (%d) достигло максимума (%d)", 
        len(jb.packets), MaxJitterBufferSize)
}
```

#### SetPtime()
- ✅ Проверка допустимых значений ptime (10-100ms)
- ✅ Возвращает `MediaError` с кодом `ErrorCodeAudioTimingInvalid`
- ✅ Включает контекстную информацию о допустимых значениях
